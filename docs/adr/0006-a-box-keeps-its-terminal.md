# A box keeps the terminal it was started in

A box runs in the terminal it was started in, and wormhole asks no multiplexer for anything: it starts no tmux session, resumes none, renames none, focuses no pane, reads no `TMUX`, and has no setting about any of it. In a tmux window, a Moshi tab, the box is that window's program, so tmux and every phone client that speaks tmux list it, show it, detach from it, reattach to it and hear its bell, with tmux and Moshi as installed. One box per window is Moshi's own layout ("Keep one agent per window when possible"). The panel runs each session on its own terminal and draws itself again when the session ends, inside tmux or not; another box wants another tab.

`wormhole attach` with no command opens a shell in the box. The agent is in the terminal the box was started in, and reaching that terminal is the multiplexer's job. The old default started a second agent session on the same home and workspace, which nobody asked for.

What the box still owes the terminal is all inside the box. It keeps the caller's PTY, with no session, process group or PTY of its own in between, so BEL, titles, focus reports and keys reach the multiplexer as the agent wrote them. `TERM` crosses with its compiled description; `TMUX` and `TMUX_PANE` never cross, since an agent that saw them would drive a tmux server it cannot reach (Claude Code's agent teams split panes under `TMUX`). Every agent rings the bell when it needs you, written into its own config where unset: Claude Code's `preferredNotifChannel = "terminal_bell"`, because its default does nothing in a terminal it does not name, tmux included; Codex's `tui.notification_condition = "always"`, because its default rings only after a focus-out, which tmux sends only with `focus-events on`. With tmux's defaults a bell marks the tab `!` and reaches every attached client.

tmux's defaults are also the safe ones, and nothing here asks to change them: `allow-passthrough off`, `set-clipboard external`, `allow-rename off`. `set-clipboard on`, which Moshi's clipboard page asks for, makes tmux answer any pane's clipboard query with the newest paste buffer, so every box reads what was last copied; tmux 3.7 and later can refuse that with `get-clipboard off`. moshi-hook and Tailscale SSH stay off a host that runs boxes: every box reaches both.

Considered and rejected: the first version of this decision, never released, which gave a tmux session of its own to every session the panel started inside tmux and to every interactive start outside a multiplexer (a handoff file run by `wormhole __hosted`, sessions renamed after boxes, `attach` focusing the pane a box recorded, `terminal = "auto" | "here" | "tmux"` in a host config). In a tab the user made for a box, it moved the client to a session nobody asked for, and it made wormhole a tmux client with rules of its own. Sending pushes: a push to a locked phone needs the owner's Moshi token and something on the host to send it, and no computer should need a tmux hook or script to run a box. Naming the tab after the box: tmux names it after the pane's foreground program, `wormhole`, and `prefix ,` names it otherwise. wormhole's own PTY supervisor: a second multiplexer no phone client speaks.
